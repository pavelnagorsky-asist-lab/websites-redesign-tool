# Общий список

Список всегда ведётся локально: `list.csv` (Excel) и `list.md` в корне рабочего пространства. Обычно он уже обновлён в конце `stitch-design`; этот процесс — для явного запроса. Локальные файлы сохраняются и после публикации в Google-таблице, чтобы данные можно было перенести вручную.

Перед отчётом скачать свежую копию общей таблицы по `docs/shared-table.md`. После пересборки `list.csv` сверить каждую компанию по домену и названию с общей таблицей, а также проверить повторы внутри локального списка. Найденные совпадения вынести в ответ пользователю; автоматически данные не удалять. Запрос «отчёт / список / итоги» сам по себе Google-таблицу не изменяет. По команде «занеси / добавь / выгрузи в таблицу» агент публикует данные в общую Google-таблицу по разделу «Запись по команде пользователя» в `docs/shared-table.md`, без повторного подтверждения. Если указан файл, источник публикации — этот файл.

1. `npx tsx scripts/validate.ts` — исправить ошибки у designed-лидов (дозаполнить поля), а не игнорировать. Без `admin` и `contactInfo` лид в таблицу не вносить.
2. Если `report.ts` пишет «проект Stitch не публичный» — `npx tsx scripts/stitch.ts verify <slug>` и разобраться (проект удалён/закрыт).
3. `npx tsx scripts/report.ts` — пересоберёт список и проставит `reportedAt` новым. Это дата внесения в локальный список, а не признак публикации в Google-таблице.
4. Ответ пользователю: таблица (компания · сфера · сайт · ссылка Stitch · админка · главный upsell), отдельно — какие добавлены сейчас; полные пути к `list.csv` / `list.md`.

`--all` — дополнительно `reports/all-<дата>.csv` со всеми лидами, включая отклонённые. Сводка по воронке: `npx tsx scripts/status.ts`.
