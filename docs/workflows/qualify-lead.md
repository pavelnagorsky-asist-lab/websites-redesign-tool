# Квалификация лида

Для каждого слага (если лида ещё нет — сначала `scripts/new-lead.ts` + `scripts/audit.ts`):

1. Прочитать `leads/<slug>/lead.json` (поле `audit`: авто-оценка, причины, сложность, CMS).
2. **Посмотреть скриншоты** (открыть картинки): `audit/desktop.jpg` и `audit/mobile.jpg`; при сомнениях — `desktop-full.jpg` / `mobile-full.jpg`. Решение принимается по картинке, авто-оценка — только подсказка.
3. Если сайт не открылся (`Сайт не открывается` в причинах): проверить через веб-запрос (fetch страницы). Если открывается там — возможна гео-блокировка, оценить по полученному контенту и пометить в `notes`. Если сайт мёртв везде — `rejected` («сайт не работает»), кроме случаев, когда бизнес явно живой (тогда это лид на «новый сайт» — пометить в ideas).
4. Применить `docs/criteria.md`: стоп-факторы → rating (outdated / potential / complexity) → решение.
5. Признаки живого бизнеса: 1 веб-поиск максимум («<название> <город> отзывы») если по сайту не видно (`activitySignals`).
6. Проверить контакты в `lead.json` (собраны аудитом) — дополнить из `audit/content.json` или страницы контактов, если пусто. Адрес — строкой.
7. Записать в `lead.json`:
   - `company` (нормальное название, без «ООО» если есть бренд), `industry`, `city`
   - `rating`: `{ "outdated": N, "potential": N, "complexity": N }`
   - `problems`: 3–5 пунктов языком владельца (см. criteria.md §3)
   - `upsell`: 1–3 конкретных пункта из `docs/upsell-catalog.md`
   - `ideas`: прочие наблюдения (например «нет карточки в Яндекс Бизнес», «можно сделать англ. версию для иностранцев»)
   - `activitySignals`
   - `status`: `qualified` или `rejected` + `rejectReason` (одна фраза)
8. `npx tsx scripts/validate.ts` — без ошибок по этим слагам.

Ответ — кратко по каждому лиду: решение, outdated/potential/complexity, главная проблема.
