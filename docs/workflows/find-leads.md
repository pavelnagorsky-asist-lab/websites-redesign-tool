# Поиск лидов

Вход: ниша, город, сколько квалифицированных лидов нужно (по умолчанию 5). Если ниша/город не заданы — выбрать по `docs/sources.md`, предпочитая ниши и города, которых ещё мало в `leads/` (`npx tsx scripts/status.ts`).

## Шаги

0. Обновить и прочитать общую таблицу команды по `docs/shared-table.md`; сохранить свежую выгрузку в `data/shared-list.csv`.

1. **Собрать кандидатов** (3–4× от нужного числа) по каналам из `docs/sources.md`. Веб-поиск — несколько запросов сразу (параллельно, если среда умеет). Сразу отсеивать по сниппетам: гос, сети, агрегаторы, Tilda/Wix, явно свежие сайты.
2. **Дубли пачкой**: `npx tsx scripts/check.ts <url1> <url2> ...` — занятые выкинуть.
3. **Создать лиды** для свободных:
   `npx tsx scripts/new-lead.ts <url> --name "<Название>" --industry "<Сфера>" --city "<Город>" --source "<откуда>"`
   Exit code 2 = дубль, пропустить.
4. **Автоаудит**: `npx tsx scripts/audit.ts --pending --concurrency 4` (≈30–60 с на сайт; запускать в фоне, если кандидатов > 6).
5. **Квалификация** — `docs/workflows/qualify-lead.md`. При > 4 лидах — если среда умеет субагентов, раздать пачки по 3–5 слагов параллельно (экономит контекст: скриншоты смотрят они); иначе по очереди.
6. Если квалифицированных меньше нужного — повторить с шага 1 (другие запросы, страницы выдачи 2–5, соседний город). Не снижать планку критериев.

## Результат пользователю

Короткая таблица: компания · сфера · город · сайт · решение (qualified/rejected) · одна фраза почему. Далее предложить сделать дизайн для qualified (`docs/workflows/stitch-design.md`).
