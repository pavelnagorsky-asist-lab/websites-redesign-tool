# Концепт редизайна в Google Stitch

Для лидов в статусе `qualified` (или по явной просьбе «сделай дизайн для X»). Результат: публичный проект Stitch, в котором **ровно 2 экрана** — главная desktop + mobile на реальном контенте компании. Ссылку отправляют клиенту как есть.

Принцип: **Stitch трогаем минимально — 2 генерации на лид, всё остальное правим локально в HTML.** Никаких правок через генерацию, черновиков и лишних экранов в проекте.

## 0. Доступ

Вся работа со Stitch — через `npx tsx scripts/stitch.ts …` (ключ `STITCH_API_KEY` из `.env` / окружения; MCP-клиент не нужен). Если скрипт пишет «STITCH_API_KEY не задан» — остановиться и сказать пользователю (README → «Ключ Stitch»). **Не подменять дизайн HTML-макетом.** Не генерировать через MCP-инструменты Stitch (если подключены): клиент обрывает долгий вызов, в проекте остаётся обрывок.

Команды:
- `stitch.ts design <slug>` — новый публичный проект + генерация desktop, затем mobile в том же стиле (4–10 мин, запускать в фоне и ждать). Скачивает `design/desktop.html`, `mobile.html`, превью `design/*-view-N.jpg`, пишет `design` в `lead.json`. При обрыве сам удаляет проект — просто запустить снова.
- `stitch.ts push <slug>` — типографика + рендер локальных HTML → залить в те же 2 экрана (без генераций, ~1 мин) + `verify`.
- `stitch.ts pull <slug>` — заново скачать HTML/превью из Stitch (затирает локальные правки).
- `stitch.ts verify <slug...>` — публичная ссылка глазами клиента: ровно 2 экрана, PUBLIC.
- `stitch.ts design <slug> --redo` — удалить проект и сгенерировать заново. Только если концепт не годится целиком (не тот стиль, сломанная вёрстка); стоит ещё 2 генерации.

## 1. Подготовка (без генераций)

Перед генерациями обновить общую таблицу по `docs/shared-table.md` и проверить выбранные лиды на совпадения `where === 'shared'`. Совпадения разобрать до расходования генераций Stitch.

1. `leads/<slug>/lead.json` — статус `qualified`.
2. `leads/<slug>/audit/content.json` — реальные тексты: заголовки, меню, услуги, цены, «о компании», контакты.
3. Посмотреть скриншоты `audit/desktop.jpg`, `audit/mobile.jpg` (открыть картинки) — фирменные цвета, логотип, что плохо.
4. `docs/design-guide.md` — структура и стилевое направление по нише. Проверить `design.style` у других лидов той же ниши/города — не повторяться.
5. Шрифты — только с кириллицей (Manrope, Inter, Montserrat, Unbounded, Golos Text, PT Sans/Serif, Lora, Newsreader).
6. Промпты по шаблону гайда → `leads/<slug>/prompt-desktop.txt`, `prompt-mobile.txt` (mobile: тот же контент + мобильное дополнение + «same visual style, colors and fonts as the desktop screen»). Все тексты — дословно с сайта.
   **Промпты видны клиенту** в истории чата проекта: писать как чистый бриф дизайнеру — без оценок текущего сайта («устаревший», «ужасный»), без внутренних пометок, лидов, цен на наши услуги.

Хороший промпт = меньше правок: чем точнее тексты, цвета и секции, тем меньше потом исправлять руками.

## 2. Генерация (2 генерации)

`stitch.ts design <slug>` → открыть все `design/desktop-view-N.jpg` и `mobile-view-N.jpg`.

## 3. Правки — локально, без Stitch

Проверка по чек-листу гайда + **выдуманные факты** (Stitch сочиняет телефоны, гарантии, сроки, «бесплатно», отзывы, ФИО, цифры, расстояния) — сверить с `content.json`.

Всё исправлять прямо в `design/desktop.html` и `design/mobile.html` обычным редактированием файла: тексты, телефоны, цвета, удалить/переставить блок, поправить отступы. Одинаковые правки — в обоих файлах. Картинки — оставлять сгенерированные Stitch или ставить фото с сайта компании (`audit/content.json` → images).

`stitch.ts push <slug>` — сам применит типографику (тире не начинает строку, предлоги не висят, телефоны не рвутся), отрендерит, зальёт в Stitch и проверит ссылку. Посмотреть обновлённые `*-view-N.jpg`; при необходимости поправить и снова `push` (бесплатно).

## 4. Запись

1. Проверить, что в `lead.json` заполнены `admin` и `contactInfo` (criteria.md §5–6); если нет — заполнить. В `lead.json` дописать `design.style` (направление, палитра, шрифты — одной строкой) и `"status": "designed"`. Остальное в `design` скрипт заполнил сам.
2. `npx tsx scripts/validate.ts`, затем `npx tsx scripts/report.ts`. Если несколько дизайнов идут параллельно — `report.ts` запускает координатор один раз в конце.

## 5. Ответ пользователю

Ссылка на проект и 1–2 фразы, что стало лучше по сравнению с текущим сайтом; известные недочёты (сгенерированные фото, предложенные доп. функции вроде Telegram-заявок).
