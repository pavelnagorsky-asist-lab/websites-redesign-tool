# Общая таблица команды и дубли

Общая итоговая таблица команды: [Sites to upgrade](https://docs.google.com/spreadsheets/d/1sZkqqTQ1yc9dtcsCOhNEup4tPUkUQvTJLsRg3EG0pRU/edit#gid=0), лист `gid=0`.

CSV для чтения: https://docs.google.com/spreadsheets/d/1sZkqqTQ1yc9dtcsCOhNEup4tPUkUQvTJLsRg3EG0pRU/export?format=csv&gid=0

Перед каждой новой пачкой поиска, началом дизайна и подготовкой итогового списка:

1. Агент скачивает CSV по ссылке выше в `data/shared-list.csv`, создав `data/`, если её нет. Сохранять исходные байты UTF-8; проверить успешный HTTP-ответ, формат CSV и заголовки `Name`, `Url`. Страницу входа или ошибку вместо CSV не сохранять. Локальная копия исключена из Git.
2. Прочитать свежие строки: компания (`Name`), сайт (`Url`), статус (`Status`), исполнитель (`Assignee`), ресурсы/дизайн (`Resources`). Учитывать все строки, включая `Declined` и строки без статуса. Повторно компании из таблицы не брать.
3. Для новых кандидатов выполнить `npx tsx scripts/check.ts <url> "<название>" ...`: он учитывает локальные лиды и скачанную таблицу. Проверять домен и название; похожие названия разбирать вручную. `www`, протокол и завершающий `/` не отличают сайты.
4. Для уже существующих локальных лидов и `list.csv` сравнивать именно с общей таблицей: `findDuplicates({ domain, name })` из `scripts/lib/leads.ts`, оставляя совпадения `where === 'shared'`. Совпадение с собственной карточкой в `leads/` ожидаемо и не является конфликтом с командой. Проверить также повторы внутри `list.csv`.
5. Если совпадение найдено, сообщить пользователю компанию, сайт, строку/исполнителя в общей таблице и характер совпадения. Уже существующие лиды и готовые дизайны не удалять и не менять их статус автоматически. Если это собственная ранее внесённая строка, считать её уже опубликованной и не добавлять повторно.

Если свежая таблица недоступна, сообщить об этом: старая копия не подтверждает отсутствие дублей.

## Запись по команде пользователя

Команды «занеси / добавь / выгрузи в таблицу», «обнови общую таблицу» означают запись в таблицу выше, на лист `gid=0`. Ссылку повторно не спрашивать. Сама команда разрешает запись без дополнительного подтверждения. Запросы «отчёт», «список», «итоги» сами по себе только обновляют локальный список и показывают результат.

1. Если источник — локальные лиды, обновить `list.csv` и `list.md` по `docs/workflows/report-leads.md`. Эти файлы сохранять и продолжать вести после публикации: они нужны как локальная копия и для ручного переноса. Если пользователь указал CSV или другой файл, переносить именно его данные; не подменять их всем локальным списком и не затирать локальный список входным файлом.
2. Непосредственно перед записью скачать свежую таблицу и проверить дубли по домену и названию, включая повторы внутри переносимых данных. Собственные ранее внесённые компании пропускать; чужие совпадения не добавлять и сообщать о них. Существующие строки, статусы, комментарии и оформление команды не перезаписывать; изменения существующих строк делать только по явной команде пользователя.
3. Добавлять только новые строки после последней занятой строки. Сопоставлять колонки по заголовкам, а не вставлять локальный `list.csv` целиком: у него другой набор полей.

   | Колонка общей таблицы | Данные |
   |---|---|
   | `Name` | Название компании |
   | `Url` | Сайт компании |
   | `Status` | Значение из указанного файла; для новых строк из лидов — пусто, статус команды не придумывать |
   | `Task` | Редизайн сайта и предлагаемый доп. функционал (`upsell`) |
   | `Resources` | Публичная ссылка на проект Stitch |
   | `Assignee` | Исполнитель из файла или `lead.assignee`; для данных Павла — `Pavel Nahorski` |
   | `Max comments` | Значение из указанного файла; для новых строк из лидов — пусто |

4. Использовать доступный инструмент Google Sheets; если он не умеет запись или недоступен — браузер через Playwright. Не просить пользователя запускать скрипты. Если запись требует недоступного доступа, сообщить конкретную причину и дать локальные файлы для ручного переноса; успешную публикацию не заявлять.
5. После записи повторно прочитать внесённый диапазон или скачать свежий CSV и сверить все ячейки с исходными данными. Обновить `data/shared-list.csv` проверенной выгрузкой. В ответе дать ссылку на таблицу, число добавленных строк и диапазон; отдельно указать пропуски/конфликты, если есть. При сбое сначала перечитать таблицу: уже сохранившиеся строки повторно не добавлять.

`reportedAt` относится только к локальному списку. Публикацию и отсутствие повторов подтверждать свежими данными Google-таблицы.
