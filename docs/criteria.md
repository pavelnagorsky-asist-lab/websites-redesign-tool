# Критерии отбора лидов

Цель — не количество, а компании, которые **реально могут заплатить** за быстрый редизайн без постоянной поддержки.

## 1. Жёсткие стоп-факторы → `rejected` сразу

| Стоп-фактор | Как распознать |
|---|---|
| Гос-организация / гос-участие | ГУ, ГУО, ГУК, ГП, РУП, КУП, КУПП, УЗ, райисполком, райпо, Белкоопсоюз, «государственное», домены `.gov.by`, `.edu.by`; крупные ОАО-заводы (закупки через icetrade / goszakupki) |
| Бизнес не работает | сайт мёртв **и** нет свежих отзывов, соцсетей и карточек на картах; «компания ликвидирована» в ЕГР |
| Сайт с логикой и приемлемым дизайном | интернет-магазин с корзиной, личный кабинет, подбор по параметрам, калькулятор, онлайн-бронирование, сложные карты — при этом дизайн «не модный, но нормальный». Денег не дадут, а логику придётся писать нам |
| Уже современный сайт | Tilda / Wix / Webflow с аккуратным дизайном, свежий WordPress-шаблон, нормальная мобильная версия |
| Крупная сеть / франшиза / федеральный бренд | сайтом управляет головной офис или агентство |
| Маркетплейс / агрегатор / сайт-визитка на чужой платформе | deal.by-страница, страница на агрегаторе, только Instagram |
| Уже занято | есть в общем списке или в `leads/` (`scripts/check.ts`) |

Исключение для «сайта с логикой»: можно брать, если очевиден **доп. функционал**, который мы сделаем отдельно от сайта (бот, форма заявки → Telegram, запись). Тогда редизайн — только витрина/главная, а логика остаётся у них.

## 2. Оценка (пишем в `rating`, шкала 0–10)

**outdated** — насколько сайт устарел визуально и технически
- 9–10: таблицы, Flash, нет мобильной версии, © 2012, мелкий текст, «сайт из нулевых»
- 7–8: адаптив есть, но кривой; дизайн 2013–2017; шаблонный WordPress/Joomla с баннером-слайдером
- 5–6: в целом нормально, но скучно/неудобно, слабый первый экран, нет CTA
- <5: современный — **не берём**

**potential** — вероятность, что заплатят
- + частная компания малого/среднего размера (ЧУП, ООО, ИП), есть живой поток клиентов
- + свежая активность: отзывы на Яндекс/Google картах за 2025–2026, Instagram/Telegram живые, цены с датой, новости
- + ниша, где сайт приносит заявки: услуги, производство на заказ, B2B-поставки, HoReCa, ремонт, медицина/красота (частные)
- + видно, что на рекламу уже тратят (контекст в выдаче, акции, промо)
- − микробизнес «на одного человека» без признаков дохода
- − всё общение ушло в Instagram, сайт заброшен годами и не нужен владельцу
- 7+ = хороший лид, 5–6 = можно, <5 = не берём

**complexity** — сколько логики придётся воссоздавать (0 = статичная визитка, 10 = магазин с ЛК)
- 0–3 — идеально
- 4–6 — только витрина + доп. функционал отдельно
- 7+ — не берём (кроме исключения выше)

**Решение:** `qualified` если outdated ≥ 6, potential ≥ 5, complexity ≤ 5. Иначе `rejected` с понятной причиной.

Автоматический `audit.outdatedScore` (0–100) — только подсказка. Финальное решение — по скриншотам глазами.

## 3. Как писать `problems` (идёт в общий список и потом владельцу)

Язык владельца бизнеса, а не разработчика. Каждая проблема — **последствие для бизнеса**. 3–5 пунктов, самое больное первым.

- ❌ «Нет meta viewport, вёрстка таблицами»
- ✅ «На телефоне сайт открывается уменьшенной десктопной версией — текст не прочитать без зума, а это 60–70% посетителей»
- ❌ «Устаревший дизайн»
- ✅ «Первый экран — баннер-слайдер без предложения и кнопки: непонятно, что делает компания и как заказать»
- ✅ «Телефон только в подвале, нет кнопок мессенджеров — клиенту сложно связаться»
- ✅ «В подвале © 2015 — сайт выглядит заброшенным, это снижает доверие»
- ✅ «Цены и услуги разбросаны по 10 страницам — нет понятного прайса»

## 4. `activitySignals` — почему считаем бизнес живым

Короткие факты со ссылками/датами: «отзывы на Яндекс.Картах, последний — окт. 2026», «Instagram, посты в ноябре 2026», «© 2026 на сайте», «акция до 30.11». Хватит 1–2 сигналов; не тратить на это больше 1–2 поисков.

## 5. `admin` — нужна ли клиенту CMS (колонка «Админка» в общей таблице)

Сайт согласившемуся клиенту отдаём zip-архивом: HTML + CSS. Если клиенту нужно самому менять контент — второй zip с простой open-source CMS. Поддержку не даём, поэтому вопрос один: **что клиент будет менять сам и чаще ли раза в квартал**.

Формат — коротко, без пояснений:

| Значение | Когда |
|---|---|
| `нет` | Лендинг/визитка; контент меняется реже раза в квартал (телефоны, услуги, цены «от») или сайт годами не обновлялся |
| `да: <что>` | Что клиент будет менять сам, 1–3 слова через запятую: `галерея` (фото работ/портфолио), `цены`, `акции`, `каталог`, `новости`, `статьи`, `даты групп` (наборы, расписание) |
| `?` | Сигналов мало — уточнить у клиента при контакте |

Сигналы на текущем сайте (`audit/content.json`, меню, `activitySignals`): разделы «Акции», «Новости», «Портфолио/Наши работы», прайс с конкретными ценами, «ближайшая группа»; свежие даты в них. Раздел есть, но последнее обновление много лет назад — скорее `нет`.

## 6. `contactInfo` — контакты для общей таблицы (колонка «Contact info»)

Одна строка: только основные телефоны и email для предложения, через запятую — `+375 (29) 123-45-67, info@site.by`. Без соцсетей, мессенджеров, адресов, подписей «факс/бухгалтерия» и телефонов отделов; при множестве номеров — только основной офис (2–3 номера максимум). Полный набор контактов остаётся в `contacts`.
