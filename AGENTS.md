# Поиск клиентов на редизайн сайтов

Инструкции для любого AI-агента (Claude Code, Codex, Cursor и т.п.). Источник правды — этот файл и `docs/`; файлы для конкретных инструментов (`CLAUDE.md`, `.claude/`, `.cursor/rules/`) только ссылаются сюда.

Это **рабочее пространство агента**, а не кодовый продукт. Пользователь пишет в чате («найди 5 типографий в Гомеле», «сделай дизайн для X», «дай отчёт»), всю работу выполняет агент. Скрипты в `scripts/` — внутренние инструменты агента: пользователю их не предлагать и не просить запускать.

## Задача (ТЗ команды)

Ищем компании (Беларусь, при необходимости РФ; сфера любая) с устаревшими, неудобными, плохо работающими на мобильных сайтами → делаем **быстрый концепт редизайна в Google Stitch** (≤ 1 часа на компанию; не идеал, а показать, как могло бы быть) → вносим в общий список (`list.csv` + `list.md` в корне): компания и сфера, ссылка на сайт, контакты (email, телефон, мессенджеры), проблемы сайта, **ссылка на дизайн в Stitch**, доп. идеи (чат-бот, Telegram/Viber, форма заказа/записи, автоматизация заявок).

Жёсткие правила:
- **Не связываться с компаниями**: ни писем, ни звонков, ни форм на их сайтах. Только сбор и подготовка.
- **Гос-организации не берём.**
- **Перед поиском, дизайном и подготовкой итогового списка обновлять общую таблицу команды** по `docs/shared-table.md`, затем проверять дубли (`scripts/check.ts`) по `leads/` (включая отклонённые) и свежей `data/shared-list.csv`. Компании из общей таблицы повторно не брать независимо от статуса строки.
- **По команде «занеси / добавь / выгрузи в таблицу»** агент сам добавляет данные в [общую Google-таблицу команды](https://docs.google.com/spreadsheets/d/1sZkqqTQ1yc9dtcsCOhNEup4tPUkUQvTJLsRg3EG0pRU/edit#gid=0), лист `gid=0`, по `docs/shared-table.md`. Это разрешение на запись, повторное подтверждение не нужно. `list.csv` и `list.md` продолжать вести всегда — локальная копия и запасной вариант для ручного переноса; успешная публикация их не заменяет.
- Не берём сайты, где есть логика (подборы, калькуляторы, корзина, ЛК, карты) при «не модном, но нормальном» дизайне — разве что под доп. функционал.
- Только небольшие задачи, отдаваемые клиенту **без постоянной поддержки**.
- Качество важнее количества: живой бизнес с потенциальным интересом.
- Дизайн — **только в Google Stitch** (не HTML-макеты).
- **Stitch трогать минимально, ссылка — сразу для клиента.** Один проект на лид, ровно 2 генерации (desktop + mobile, `stitch.ts design`), в проекте только эти 2 экрана. Все правки — локально в `design/*.html` и `stitch.ts push` (без генераций; сам делает типографику и проверку ссылки). Никаких `edit`/перегенераций в том же проекте: интерфейс Stitch показывает каждый экран и историю промптов, удалить их нельзя.
- **Типографика в макете:** тире не начинает строку, предлоги не висят, телефоны не рвутся — делает `push`.
- Промпты видны клиенту в истории проекта — писать как чистый бриф, без оценок текущего сайта и внутренних пометок.
- Только реальный контент компании; выдуманные Stitch факты (гарантии, сроки, отзывы, ФИО, цифры) убирать.

## Процессы

| Пользователь говорит | Делать |
|---|---|
| «найди компании / лиды», «ещё N в нише X» | `docs/workflows/find-leads.md` → `docs/workflows/qualify-lead.md` |
| «оцени сайт X», «стоит ли брать» | `new-lead` + `audit` → `docs/workflows/qualify-lead.md` |
| «сделай дизайн / редизайн для X» | `docs/workflows/stitch-design.md` (несколько лидов параллельно — не больше 3 одновременно, лимиты Stitch) |
| «сделай N под ключ» | find-leads → qualify-lead → stitch-design для qualified → report-leads |
| «отчёт», «список», «итоги» | `docs/workflows/report-leads.md` |
| «занеси / добавь / выгрузи в таблицу», «обнови общую таблицу» | `docs/workflows/report-leads.md` → публикация в Google-таблицу по `docs/shared-table.md`; если указан файл, переносить данные из него |
| «что у нас есть», «статус» | `npx tsx scripts/status.ts` |

Статусы лида: `candidate → audited → qualified | rejected → designed`; `reportedAt` — внесён в локальный список (ставит `report.ts`), не подтверждение публикации в Google-таблице.

## Инструменты (`npx tsx scripts/<name>.ts`)

- `check.ts <url|название> ...` — дубли в `leads/` + свежей выгрузке общей таблицы `data/shared-list.csv` (обновление: `docs/shared-table.md`); exit 2 = занято
- `new-lead.ts <url> --name --industry --city [--source]` — создать `leads/<slug>/lead.json` (сам проверяет дубли)
- `audit.ts <slug...> | --pending [--concurrency N]` — Playwright: скриншоты desktop/mobile, адаптивность, устаревшая вёрстка, CMS, признаки сложной логики, контакты, тексты и картинки для дизайна
- `validate.ts` — полнота lead.json для текущего статуса
- `report.ts [--all]` — пересобрать `list.csv` (Excel, `;`) + `list.md` из designed-лидов; `--all` — ещё `reports/all-<дата>.csv`
- `status.ts` — воронка
- `stitch.ts design <slug> [--redo] | push <slug> | pull <slug> | verify <slug...>` — вся работа с Google Stitch (подробно — `docs/workflows/stitch-design.md`). Скрипт сам ходит в Stitch API по `STITCH_API_KEY` (`.env`, переменная окружения или реестр Windows); MCP-клиент агенту не нужен.

## Данные

Лиды и результаты работы принадлежат пользователю: `leads/`, `list.csv`, `list.md`, `reports/`, `tmp/` и `data/shared-list.csv` хранятся локально и не включаются в Git. Каждый пользователь собирает свою базу; не добавлять эти пути принудительно через `git add -f`.

```
leads/<slug>/                slug = домен, точки → дефисы (printex.by → printex-by)
  lead.json                  карточка лида (схема: scripts/lib/leads.ts → interface Lead)
  audit/desktop.jpg, mobile.jpg, *-full.jpg   текущий сайт
  audit/audit.json           технические данные
  audit/content.json         тексты, меню, картинки, контакты — сырьё для промпта Stitch
  stitch-prompt.md           промпты, отправленные в Stitch
  prompt-desktop.txt, prompt-mobile.txt   промпты для Stitch
  design/desktop.html, mobile.html   HTML экранов — правки здесь, потом stitch.ts push
  design/*-view-N.jpg        превью экранов для просмотра
list.csv, list.md            локальный список и копия для ручного переноса (генерирует report.ts, руками не править)
docs/criteria.md             критерии отбора и как писать проблемы
docs/sources.md              где и как искать
docs/design-guide.md         как делать концепт в Stitch, шаблон промпта
docs/upsell-catalog.md       доп. функционал без поддержки
docs/workflows/*.md          пошаговые процессы (поиск, квалификация, дизайн, отчёт)
```

`lead.json` редактировать напрямую. Отклонённые лиды не удалять — они защищают от повторной проверки. Файлы лида писать только внутри `leads/<slug>/`.

## Стиль работы

- Отвечать по-русски, коротко: таблица/список результатов, без пересказа процесса.
- Независимые действия — параллельно, если среда умеет (поисковые запросы, аудит пачкой, субагенты на разные лиды).
- Скриншоты **смотреть глазами** (открыть картинку) — решение по картинке, авто-оценка лишь подсказка.
- Экономить генерации Stitch (месячный лимит): 2 на лид; правки — только локально в HTML.
- Долгие команды (`stitch.ts design` 4–10 мин, `push` ~1,5 мин; `audit.ts` пачкой) — в фоне с логом, если среда обрывает команды по таймауту.
- Коммитить только по просьбе пользователя.
