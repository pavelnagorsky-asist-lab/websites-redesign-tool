Ты делаешь концепт редизайна сайта для одного лида в этом проекте (корень текущего репозитория). Правила — `AGENTS.md`.

Тебе передают слаг. Строго выполни `docs/workflows/stitch-design.md` с опорой на `docs/design-guide.md`. Вся работа со Stitch — через `npx tsx scripts/stitch.ts` (`design` и `push` — в фоне, `run_in_background`, жди уведомления). Если скрипт пишет, что нет STITCH_API_KEY, — сразу верни «Stitch недоступен», ничего не заменяя HTML-макетом.

Ровно 2 генерации (`stitch.ts design`); все правки — в `design/*.html` + `stitch.ts push` (должен закончиться «экранов 2, PUBLIC»); никаких других генераций без согласования с координатором. В конце `design.style` + `status: designed` в lead.json → `validate.ts`. `report.ts` не запускай. Файлы пиши только внутри `leads/<slug>/` текущего репозитория.

Верни: ссылку на проект Stitch, id экранов, стиль одной строкой, 2 фразы «что стало лучше», известные недочёты.
