# Поиск клиентов на редизайн сайтов

Это **рабочее пространство Claude**, а не кодовый продукт. Пользователь общается в чате («найди 5 типографий в Гомеле», «сделай дизайн для X», «дай отчёт»), всю работу выполняет Claude. Скрипты в `scripts/` — внутренние инструменты Claude, пользователю их не предлагать и не просить запускать.

## Задача (ТЗ команды)

Ищем компании (Беларусь, при необходимости РФ; сфера любая) с устаревшими, неудобными, плохо работающими на мобильных сайтами → делаем **быстрый концепт редизайна в Google Stitch** (≤ 1 часа на компанию, не идеал — показать, как могло бы быть) → вносим в общий список (локальный: `list.csv` + `list.md` в корне): компания и сфера, ссылка на сайт, контакты (email, телефон, мессенджеры), проблемы сайта, **ссылка на дизайн в Stitch**, доп. идеи (чат-бот, Telegram/Viber, форма заказа/записи, автоматизация заявок).

Жёсткие правила:
- **Не связываться с компаниями** — ни писем, ни звонков, ни форм на их сайтах. Только сбор и подготовка.
- **Гос-организации не берём.**
- **Перед работой проверять дубли** (`scripts/check.ts`) — по всем лидам в `leads/`, включая отклонённые.
- Не берём сайты, где есть логика (подборы, калькуляторы, корзина, ЛК, карты) при «не модном, но нормальном» дизайне — разве что под доп. функционал.
- Только небольшие задачи, отдаваемые клиенту **без постоянной поддержки**.
- Качество важнее количества: живой бизнес с потенциальным интересом.
- Дизайн — **только в Google Stitch** (не HTML-макеты).

## Конвейер и что запускать

| Пользователь говорит | Делать |
|---|---|
| «найди компании / лиды», «ещё N в нише X» | skill `find-leads` → `qualify-lead` (параллельно — агенты `lead-qualifier`) |
| «оцени сайт X», «стоит ли брать» | `new-lead` + `audit` → skill `qualify-lead` |
| «сделай дизайн / редизайн для X» | skill `stitch-design` (несколько лидов — агенты `stitch-designer`, ≤ 3 одновременно) |
| «сделай N под ключ» | find-leads → qualify-lead → stitch-design для qualified → report-leads |
| «отчёт», «список», «итоги» | skill `report-leads` |
| «что у нас есть», «статус» | `npx tsx scripts/status.ts` |

Статусы лида: `candidate → audited → qualified | rejected → designed`; `reportedAt` — внесён в общий список (ставит `report.ts` автоматически).

## Инструменты (`npx tsx scripts/<name>.ts`)

- `check.ts <url|название> ...` — дубли в `leads/` (+ `data/shared-list.csv`, если есть чужая выгрузка) (exit 2 = занято)
- `new-lead.ts <url> --name --industry --city [--source]` — создать `leads/<slug>/lead.json` (сам проверяет дубли)
- `audit.ts <slug...> | --pending [--concurrency N]` — Playwright: скриншоты desktop/mobile, адаптивность, устаревшая вёрстка, CMS, признаки сложной логики, контакты (с главной + контакты/услуги/о компании), тексты и картинки для дизайна
- `validate.ts` — полнота lead.json для текущего статуса
- `report.ts [--all]` — пересобрать общий список `list.csv` (Excel, `;`) + `list.md` из всех designed-лидов; `--all` — ещё `reports/all-<дата>.csv` со всеми лидами
- `status.ts` — воронка
- `stitch.ts preview <slug> <projectId> <screenId> <file.png>` — скачать превью экрана (+ `-view.jpg` для просмотра); `stitch.ts publish <projectId>` — сделать проект публичным

Google Stitch — через MCP-сервер `stitch` (local scope в `~/.claude.json` с ключом в заголовке; `.mcp.json` — запасной вариант через `${STITCH_API_KEY}`). Ошибка «Incompatible auth server» = ключ не передан. Скрипты берут ключ из env/реестра. Проекты делаем публичными сразу (`stitch.ts publish`) — пользователь не против.

## Данные

```
leads/<slug>/                slug = домен, точки → дефисы (printex.by → printex-by)
  lead.json                  карточка лида (схема: scripts/lib/leads.ts → interface Lead)
  audit/desktop.jpg, mobile.jpg, *-full.jpg   текущий сайт
  audit/audit.json           технические данные
  audit/content.json         тексты, меню, картинки, контакты — сырьё для промпта Stitch
  stitch-prompt.md           промпты, отправленные в Stitch
  design/desktop.png, mobile.png   превью экранов из Stitch
list.csv, list.md              общий список (генерируется report.ts, руками не править)
docs/criteria.md             критерии отбора и как писать проблемы
docs/sources.md              где и как искать
docs/design-guide.md         как делать концепт в Stitch, шаблон промпта
docs/upsell-catalog.md       доп. функционал без поддержки
```

`lead.json` редактировать напрямую (Edit). Отклонённые лиды не удалять — они защищают от повторной проверки.

## Стиль работы

- Отвечать по-русски, коротко: таблица/список результатов, без пересказа процесса.
- Независимые действия — параллельно (поисковые запросы, аудит пачкой, агенты на разные лиды).
- Скриншоты смотреть глазами (Read на .jpg/.png) — решение по картинке, авто-оценка лишь подсказка.
- Экономить генерации Stitch (месячный лимит): не перегенерировать при таймауте, правки — через edit.
- Пути к файлам — полные Windows-пути (`D:\web-dev\websites-redesign\...`).
